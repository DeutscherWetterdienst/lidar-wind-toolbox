Calculation paths

A code-level guide to how the Lidar Wind Toolbox turns measurements into wind products or turbulence dissipation estimates. This page is only about calculations: it does not describe the wider package architecture, file workflows, or DDD migration.

How to read this: follow each column from top to bottom. Steps with the same color represent the same calculation idea, even when the input adapter or the scientific details differ. The experimental wind path is shown separately because it has a separate compatibility entrypoint, but it currently reaches the same numerical core as the standard wind paths.

1 · Standard Halo VAD

Halo scan data → horizontal wind vector and diagnostics

Convert the Halo dataset
retrieval.xarray_adapter.halo_scan

Rename the instrument fields into a typed LidarScan: time, azimuth, elevation, radial velocity, SNR, beta, range, and optional spectral width.

Read parameters and make time bins
RetrievalParameters.from_legacy_config
build_time_grid

Turn configuration values into calculation settings, then assign every measurement ray to a time interval.

Group rays into consensus beams
_consensus_beams → consensus

Group nearby azimuths, reject weak or inconsistent radial velocities, and average the most plausible velocity cluster for each direction and height.

Build the viewing geometry
retrieval.geometry.build_Amatrix

Convert each beam’s azimuth and elevation into the coefficients that relate the unknown wind vector to the measured line-of-sight velocity.

Solve for u, v, and w
np.linalg.lstsq

For every time bin and range gate, fit the three-dimensional wind vector that best explains the selected radial velocities.

Estimate uncertainty and quality
covariance · r² · CN · finalize_quality

Propagate beam uncertainty, calculate fit quality and conditioning, convert the vector to speed and direction, and apply quality flags.

Create the Level-2 dataset
retrieval.xarray_adapter.result_to_xarray

Expose wind components, speed, direction, uncertainties, diagnostics, coordinates, and metadata as an xarray dataset.

2 · WindCube DBS

WindCube scan data → horizontal wind vector and diagnostics

Convert the WindCube dataset
retrieval.xarray_adapter.windcube_scan

Translate WindCube names and units into the same typed LidarScan used by the domain calculation.

Read parameters and make time bins
RetrievalParameters.from_legacy_config
build_time_grid

Use the configured averaging interval and assign each WindCube ray to its time bin.

Group rays into consensus beams
_consensus_beams → consensus

Apply the same SNR, beta, velocity-range, and cluster-consensus logic used by the standard array calculation.

Build the viewing geometry
retrieval.geometry.build_Amatrix

Use the WindCube beam directions to create the equations connecting line-of-sight velocities to the three wind components.

Solve for u, v, and w
domain.calculation.retrieve_array

Fit the wind vector with least squares for each time and height cell. The numerical solver is shared with standard VAD.

Estimate uncertainty and quality
covariance · r² · CN · finalize_quality

Calculate fit residuals, uncertainty, condition number, speed, direction, and quality flags.

Create the Level-2 dataset
retrieval.xarray_adapter.result_to_xarray

Serialize the common wind result into the standard Level-2 variables and metadata.

3 · Experimental wind retrieval

Experimental entrypoint → the same array retrieval core

Select experimental adapter
main_proc.py → retrieval.experimental

The configuration flag selects experimental compatibility functions. This changes the entrypoint, not the numerical algorithm currently used underneath.

Convert the input dataset
experimental.lvl2vad_standard
or experimental.lvl2wcdbs

Choose the Halo or WindCube scan adapter and create the same typed LidarScan as the normal path.

Read parameters and make time bins
RetrievalParameters.from_legacy_config
build_time_grid

Build the typed calculation settings and the time grid used by the common retrieval core.

Select consensus beams
_consensus_beams → consensus

Use the current consensus selection and quality thresholds to reduce many raw rays to representative beam velocities.

Build the viewing geometry
build_Amatrix

Turn beam directions into the matrix needed for a three-component wind fit.

Run the shared numerical core
domain.calculation.retrieve_array

Perform the same least-squares vector retrieval as Standard VAD or WindCube DBS, depending on the selected experimental adapter.

Keep richer diagnostics in the result
WindRetrievalResult → result_to_xarray

Retain the array result’s uncertainty, fit, component, consensus, and quality information before serialization.

Create the Level-2 dataset
retrieval.xarray_adapter.result_to_xarray

Write the result using the same output adapter and variable layout as the normal wind paths.

4 · Vertical stare / epsilon

Vertical Doppler velocity + wind support → turbulence dissipation

Build the stare input dataset
stare_proc.lvl2_stare_epsilon

Select Doppler velocity, intensity, time, and range from the stare Level-1 dataset and select horizontal wind speed from the wind Level-2 dataset.

Create averaging bins
pd.date_range · binsize

Divide the day into configured time windows. The final turbulence values will be reported at the midpoint of each window.

Screen Doppler velocity with SNR
stare_calc.screen_stare_dv_with_snr
NoisyData.screen_data

Estimate background noise from the upper gates, reject weak or persistently negative signals, and mask unusable Doppler velocities.

Prepare wind support
build_u_for_epsilon_xr

Make a usable horizontal-wind field by smoothing in time and height, interpolating gaps, and recording how each value was filled.

Measure lagged variability
binned_autocovariances
lagged_autocovariance

Within each time window, compare the velocity signal with time-shifted copies to measure how rapidly the fluctuations decorrelate.

Separate atmospheric and noise variance
lenschow_noise_correction

Fit the small-lag autocovariance trend. Its intercept estimates atmospheric variance, while the difference from total variance estimates noise variance.

Calculate epsilon
epsilon_from_oconnor_variance
oconnor_length_scales

Combine atmospheric variance, wind speed, sampling time, averaging length, height, and the Kolmogorov constant to estimate the turbulent energy dissipation rate.

Build turbulence quality fields
qepsilon · uncertainty helpers

Require valid variance, wind support, and epsilon values; optionally propagate uncertainty from variance sampling and wind-support filling.

Create the stare Level-2 product
stare_output_to_xarray

Return epsilon, variance, wind support, screening diagnostics, sample counts, flags, and coordinates on a clean time-height grid.

Important implementation notes

Why Standard VAD, WindCube DBS, and Experimental Wind look similar

All three wind columns eventually create a LidarScan and call domain.calculation.retrieve_array. The adapter determines how instrument fields become typed arrays; the method determines small calculation details such as velocity folding range; the shared core performs the beam consensus, geometry fit, uncertainty calculation, and result construction.

Why stare is not another wind-vector retrieval

A vertical stare observes one fixed direction over time. It does not provide the multiple beam directions needed to solve u, v, and w by VAD/DBS geometry. Instead, it uses the time variability of vertical velocity together with horizontal wind support to estimate turbulence dissipation.
